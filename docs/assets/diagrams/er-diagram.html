Figure 5.1: SmartServe AI – Relational Database Entity-Relationship (ER) Diagram
usersEntity
PK id BIGSERIAL
name VARCHAR(255) NOT NULL
email VARCHAR(255) UNIQUE
password VARCHAR(255) (Bcrypt)
role VARCHAR(50) (ROLE_*)
created_at TIMESTAMP
service_providerEntity
PK id BIGSERIAL
name VARCHAR(255) NOT NULL
email VARCHAR(255)
phone VARCHAR(50)
available BOOLEAN DEFAULT TRUE
avatar_url VARCHAR(500)
servicesEntity
PK id BIGSERIAL
title VARCHAR(255) NOT NULL
description TEXT
category VARCHAR(50) (ENUM)
price DOUBLE PRECISION
FK provider_id BIGINT → provider
bookingsEntity
PK id BIGSERIAL
FK user_id BIGINT → users.id
FK service_id BIGINT → services.id
status VARCHAR(50) (CONFIRMED/FLAGGED)
risk_score INT (0 - 100)
fraud_message VARCHAR(255)
payment_status VARCHAR(50) (SUCCESS/FAILED)
payment_tx_id VARCHAR(100)
scheduled_at TIMESTAMP
duration_minutes INT (30 - 240)
created_at TIMESTAMP
ratingsEntity
PK id BIGSERIAL
FK user_id BIGINT → users.id
FK service_id BIGINT → services.id
score INT CHECK (score 1-5)
comment TEXT
created_at TIMESTAMP
user_behavior_historyEntity
PK id BIGSERIAL
FK user_id BIGINT → users.id
FK service_id BIGINT → services.id
action VARCHAR(50) (BOOKING/VIEW)
metadata VARCHAR(500)
created_at TIMESTAMP
Key Relationships & Cardinality:
• users (1) — (∞) bookings: A user can initiate many bookings.
• services (1) — (∞) bookings: A local service can be booked multiple times.
• service_provider (1) — (∞) services: A verified provider registers and offers multiple services.
• users (1) — (∞) ratings: Customers evaluate services with 1 to 5 star scores and textual reviews.
• users (1) — (∞) user_behavior_history: Real-time personalization tracking actions for collaborative filtering.
